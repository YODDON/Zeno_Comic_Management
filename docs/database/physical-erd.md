# Physical ERD — Field-level Blueprint (unmigrated)

**Status:** field-level blueprint; SQL migrations, FKs, physical indexes and full OpenAPI need implementation verification. Names below are canonical unless explicitly marked proposed. Types: UUID IDs, `timestamptz` UTC, `bigint` money/coins, `version bigint` on mutable aggregates. String statuses validated in application and with CHECK where stable.

## Identity and Catalog
- `identity.users`: `id uuid PK`, `display_name varchar(120) NOT NULL`, `email varchar(320)`, `avatar_url text NULL`, `role varchar(16)`, `status varchar(24)`, `created_at`, `updated_at timestamptz`, `version bigint`.
- `identity.google_identities`: `user_id uuid FK`, `google_subject varchar(255) UNIQUE NOT NULL`, `linked_at timestamptz`.
- `catalog.comics`: `id uuid PK`, `slug varchar(200) UNIQUE`, `title`, `description`, `series_status`, `publication_status`, `first_published_at timestamptz NULL`, `cover_asset_id`, `default_price_coins bigint CHECK>=0`, `default_vip_eligible boolean`, `version`, timestamps; public-list index `(publication_status,updated_at DESC,id DESC)`.
- `catalog.chapters`: `id uuid PK`, `comic_id uuid FK`, `chapter_label varchar(120)`, `sort_order integer`, `price_override_coins bigint NULL CHECK>=0`, `vip_override boolean NULL`, `publication_status`, `published_at timestamptz NULL`, `version`, timestamps; unique `(comic_id,sort_order)`; CHECK Published implies non-null `published_at`; public-list index `(comic_id,publication_status,sort_order,id)` and reader-update index `(comic_id,publication_status,published_at DESC,id DESC)`.
- `catalog.chapter_pages`: `id uuid PK`, `chapter_id uuid FK`, `page_order integer`, `cloudinary_public_id text`, `asset_status varchar(24)` (`Pending|Ready`), `upload_fingerprint varchar(80)`, `upload_created_at timestamptz`, `width integer`, `height integer`; unique `(chapter_id,page_order)`, unique `cloudinary_public_id`, and operational index `(asset_status,upload_created_at)`. New intents use `sha256:<lowercase hex>`; migrated pre-fingerprint rows retain a `legacy:<page-id>` sentinel rather than losing data. `Pending` is a durable upload intent with zero dimensions; `Ready` requires positive width/height and is the only status valid for publication.
- `catalog.genres(id,slug UNIQUE,name)`, `authors(id,name)`, `translation_groups(id,name)`; join tables composite PK `(comic_id,dimension_id)`.
- `catalog.featured_comics`: `comic_id uuid PK FK`, `display_order integer UNIQUE`, `enabled boolean`; max five and Published eligibility via transactional command; configuration/version aggregate for conflict detection.

- `reading.reading_progress`: composite PK `(user_id,comic_id)`, `last_chapter_id uuid FK`, `last_page_order integer CHECK>=1`, `last_page_offset_ratio numeric CHECK BETWEEN 0 AND 1`, `accepted_max_progress_basis_points integer CHECK BETWEEN 0 AND 10000`, `last_read_at timestamptz`, `source_session_id uuid FK`, `source_session_started_at timestamptz`, `version bigint`; indexes `(user_id,last_read_at DESC)`, `comic_id`, `last_chapter_id`, and `source_session_id`. Source session/start prevents an older parallel tab from overwriting newer progress; accepted maximum progress is copied from the authoritative R02 session whenever its heartbeat is persisted.
- `reading.chapter_unlocks`: `id uuid PK`, `user_id uuid FK`, `chapter_id uuid FK`, `wallet_operation_id uuid UNIQUE`, `price_paid_coins bigint`, `unlocked_at`; unique `(user_id,chapter_id)`.
- `reading.comic_follows`: composite PK `(user_id,comic_id)`, `followed_at timestamptz`; restrictive FKs to `identity.users` and `catalog.comics`; keyset index `(user_id,followed_at DESC,comic_id DESC)` plus `(comic_id)` for reverse lookup. The first insert and `Reading.ComicFollowed.v1` outbox row are atomic; unfollow deletes only the ownership row.
- `interaction.comic_ratings`: composite PK `(user_id,comic_id)`, `stars smallint CHECK 1..5`, timestamps.
- `interaction.comments`: `id uuid PK`, `user_id`, `comic_id uuid NULL`, `chapter_id uuid NULL`, `parent_id uuid NULL`, `body text`, `status`, timestamps, `version`; CHECK exactly one Comic/Chapter target. Application validates parent depth <=1 and same target.

## Billing and Refund
- `billing.payment_orders`: `id uuid PK`, `user_id uuid FK`, `order_code varchar(64) UNIQUE`, `order_type varchar(32)`, `amount_vnd bigint CHECK>0`, `paid_coins_snapshot bigint NULL`, `vip_plan_id uuid NULL FK membership.vip_plans`, `vip_duration_hours_snapshot integer NULL`, `vip_discount_percent_snapshot integer NULL`, `provider varchar(32)`, `provider_payment_status varchar(32)`, `fulfillment_status varchar(32)`, `idempotency_key varchar(200)`, `request_fingerprint varchar(64)`, `order_status Pending|Expired|Succeeded`, `expires_at timestamptz CHECK expires_at>created_at`, `expired_at timestamptz NULL`, `verified_paid_at NULL`, `fulfilled_at NULL`, `created_at`, `version`. Unique `(user_id,order_type,idempotency_key)` permanently retains operation identity; alternate keys `(id,user_id)` and `(id,user_id,order_type)` support owned references. Type CHECK requires exact TopUp snapshots or a VipPurchase snapshot with 720 hours/20%; the lifecycle CHECK binds Pending to pending/not-started/null success timestamps, Expired to monotonic `expired_at>=expires_at`, and Succeeded to verified/fulfilled/non-null success timestamps. PostgreSQL time is sampled after locks and permits Pending→Succeeded only before expiry. TopUp TTL is `Billing:TopUpOrderTtlMinutes`; VIP TTL is independently `Membership:VipOrderTtlMinutes`; both default to 30.
- `billing.provider_transactions`: `id uuid PK`, `provider varchar(32) CHECK SePay`, `provider_transaction_id varchar(128)`, `payload_fingerprint varchar(64)`, `amount_vnd bigint CHECK>0`, `direction Incoming|Outgoing`, `payment_code varchar(64) NULL`, `account_number_last4 varchar(4)`, `reference_code varchar(128) NULL`, `matched_order_id uuid NULL FK RESTRICT`, `occurred_at`, `verified_at`, `processing_status Received|ReconciliationRequired|Fulfilled`, `reconciliation_reason varchar(64) NULL`; unique `(provider,provider_transaction_id)`. `Fulfilled` requires a matched order and no reconciliation reason; reconciliation requires a reason and may retain the matched order. `occurred_at` is evidence only and cannot override TopUp or VipPurchase expiry.
- `billing.webhook_deliveries`: `id uuid PK`, `provider_transaction_id uuid FK RESTRICT` (effective non-null via CHECK), `received_at`, `auth_verified boolean CHECK TRUE`, `payload_reference varchar(64)` (SHA-256), `delivery_reference varchar(128) NULL`, `processing_result Accepted|Duplicate|ReconciliationRequired`, `error_code varchar(64) NULL`; a row is written for each authenticated delivery in the same transaction as provider-event ingestion. Financial deduplication is exclusively the provider transaction alternate key, never delivery identity.
- `billing.refund_requests`: `id uuid PK`, `payment_order_id uuid UNIQUE FK`, `user_id`, `reason text`, `original_amount_vnd bigint`, `fee_amount_vnd bigint`, `net_refund_vnd bigint`, `required_recovery_coins bigint`, `status varchar(40)`, `requested_at`, `reviewed_by/at NULL`, `approved_by/at NULL`, `completed_by/at NULL`, `decision_reason NULL`, `version`; at most one request/order even when rejected.
- `billing.refund_recipients`: `id uuid PK`, `refund_request_id uuid UNIQUE FK`, `bank_code`, `account_number_encrypted bytea`, `account_holder_encrypted bytea`, `account_number_last4 varchar(4)`, `encryption_key_version`, `created_at`.
- `billing.refund_transfer_records`: `id uuid PK`, `refund_request_id uuid FK`, `bank_reference NULL`, `amount_vnd bigint`, `status`, `evidence_reference NULL`, `recorded_by`, `recorded_at`, `verified_at NULL`; unique normalized actual bank reference when reliable. Transfer ambiguity keeps reservation.

## Wallet
- `wallet.wallets`: `user_id uuid PK FK`, `paid_available bigint DEFAULT 0 CHECK>=0`, `paid_reserved bigint DEFAULT 0 CHECK>=0`, `bonus_available bigint DEFAULT 0 CHECK>=0`, `version`, timestamps.
- `wallet.paid_coin_lots`: `id uuid PK`, `user_id uuid FK`, `topup_order_id uuid UNIQUE`, `topup_order_type varchar(32) CHECK='TopUp'`, composite FK `(topup_order_id,user_id,topup_order_type)` to `billing.payment_orders(id,user_id,order_type)`, `granted_coins bigint CHECK>0`, **`spent_coins bigint DEFAULT 0`, `refunded_coins bigint DEFAULT 0`, `reserved_coins bigint DEFAULT 0`**, all >=0, `created_at`, `version`, CHECK `granted_coins >= spent_coins + refunded_coins + reserved_coins` using numeric casts to avoid arithmetic overflow. This validated relation enforces ownership and prevents VIP orders from backing a PaidCoinLot. The B03 migration backfills valid B01 lots to `TopUp` and fails with an explicit reconciliation precondition instead of silently dropping or misclassifying unmatched legacy lots.
- `wallet.wallet_operations`: `id uuid PK`, `user_id uuid FK`, `operation_type`, `source_type`, `source_id uuid`, `idempotency_key NULL`, `created_at`; unique `(operation_type,source_type,source_id)` for one-shot business operations and partial unique `(user_id,operation_type,idempotency_key) WHERE idempotency_key IS NOT NULL`; separate phases have distinct operation types. Rows are append-only through application and database guards.
- `wallet.wallet_entries`: `id uuid PK`, `operation_id uuid`, `user_id uuid FK`, `coin_type` Paid/Bonus, `bucket` Available/Reserved, `delta_coins bigint NOT NULL CHECK<>0`, `leg_order integer CHECK>=1`, `created_at`; composite FK `(operation_id,user_id)` preserves operation ownership, unique `(operation_id,leg_order)`, cursor index `(user_id,created_at DESC,id DESC)`. Rows are append-only through application and database guards; Bonus cannot use the Reserved bucket.
- `wallet.wallet_allocations`: `id uuid PK`, `operation_id uuid FK`, `paid_coin_lot_id uuid FK`, `amount_coins bigint CHECK>0`, `created_at`; unique `(operation_id,paid_coin_lot_id)`.
- `wallet.coin_reservations`: `id uuid PK`, `refund_request_id uuid UNIQUE FK`, `paid_coin_lot_id uuid FK`, `amount_coins bigint CHECK>0`, `status` Reserved/Consumed/Released, `created_at`, `resolved_at NULL`.

## Admin and infrastructure
- `administration.audit_logs`: `id uuid PK`, `actor_id`, `action`, `target_type`, `target_id`, `correlation_id`, `occurred_at`, `redacted_changes jsonb`; append-only database trigger; indexes `(target_type,target_id,occurred_at)` and `(actor_id,occurred_at)`.
- `administration.typed_settings`: `key varchar(100) PK`, `value_json jsonb`, `version`, `updated_at`; fixed policies (e.g. 300 cap) not writable.
- `infrastructure.outbox_messages`: `id uuid PK`, `event_type`, `payload jsonb`, `occurred_at`, `available_at`, `status`, `attempt_count`, `locked_until NULL`, `last_error_redacted NULL`; index `(status,available_at)`. An event with no registered consumer is deferred as Pending without consuming the retry budget, so a later task can register the real consumer without losing earlier integration events.
- `infrastructure.processed_messages`: composite PK `(consumer,message_id)`, `processed_at`.
- `infrastructure.idempotency_records`: unique `(actor_scope,operation_type,idempotency_key)` and request fingerprint, response/result reference, TTL policy (proposed implementation detail).
