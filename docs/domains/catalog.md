# Catalog Module

## Model
Comic with title, unique stable slug, description, cover, genres/authors/translation groups (separate M:N), publication Draft/Published/Hidden, series Ongoing/Completed/Hiatus, default price and VIP eligible. Chapter has freeform `chapter_label`, numeric `sort_order`, nullable price override (`NULL` inherit, `0` free), nullable VIP override, publication state and nullable `published_at`; each transition into Published records the publication instant. Ordered valid pages use Cloudinary. A chapter page asset is `Pending` while its durable upload intent exists but provider metadata is not confirmed, and `Ready` only after the authenticated Cloudinary asset identity and positive width/height are confirmed. Each new upload intent stores a SHA-256 content fingerprint; reuse of the same page identity with different content is a conflict, not a retry. Only `Ready` pages are valid for publication. Featured max five Published Comics with ordered positions.

## Publication
Chapter may become Published under Draft Comic, but not visible. Comic Publish requires >=1 Published Chapter with >=1 valid page. Do not Hide last valid Published Chapter while Comic Published; editing/removing page may not invalidate this either. Slug permanently immutable after *first* publish (`first_published_at`). Comic/Chapter with read/payment history cannot be hard-deleted; use Hidden. Public exposure requires both parent Comic and Chapter Published.

## API
Public comic search/filter/sort, detail, chapter Load More 30, featured. Admin comics/chapters CRUD, publish/hide, upload page ordering, metadata/taxonomy, Featured GET/PUT with version. Chapter list response includes batched access projection instead of one HTTP query per chapter. Save reorder atomically, account for unique-position collisions.

C03 implements the Admin publication commands as `POST /api/v1/admin/comics/{comicId}/publish`, `POST /api/v1/admin/comics/{comicId}/hide`, `POST /api/v1/admin/chapters/{chapterId}/publish`, and `POST /api/v1/admin/chapters/{chapterId}/hide`, each with `{expectedVersion}`. It also implements the `PATCH /api/v1/admin/comics/{comicId}/slug` command with `{slug,expectedVersion}` so the permanent first-publication slug lock is enforced through the production path; A01 editors reuse that invariant. These commands require the Admin policy and authenticated unsafe requests require CSRF. Mutations use one PostgreSQL transaction, lock in `Comic -> Chapter` order, revalidate the relevant facts after locking, and append a redacted immutable audit record with actor and correlation identity in that same transaction. A shared Chapter domain guard must be invoked by future page edit/removal commands so a Published Chapter cannot be left without a `Ready` page with positive dimensions.

A01 supplies the full Admin editor production paths for Comic/Chapter metadata and taxonomy links without bypassing C03 publication commands. Existing records use optimistic versions and every mutation is audited transactionally. Featured is a singleton versioned aggregate: save accepts at most five distinct currently Published Comics, replaces positions atomically and rejects stale versions. Featured save locks its singleton and then selected Comic rows in ascending ID order before reapplying the canonical public/content predicate. Publication and Chapter-page workflows lock the owning Comic before changing visibility-bearing state, so hide/unpublish and Featured curation serialize. Public Featured reads reuse the same Catalog public predicate and omit entries hidden after curation. Admin root/version plus taxonomy/page projections execute in one repeatable-read snapshot.

A01 Chapter-page administration exposes an authoritative Admin manifest plus append, complete-manifest reorder, replace and remove commands. Every command uses the Chapter version, locks the owning Comic, Chapter and then pages, samples PostgreSQL time after the lock, invokes the shared publication guard and writes its audit row in the same transaction. Uploading a new asset precedes the metadata transaction so a provider call never holds database locks; every unsuccessful exit after provider success attempts best-effort deletion of all uncommitted assets. Replacement/removal deletes the superseded provider asset only after commit. Failed compensation or post-commit cleanup records provider name, Cloudinary public ID, Chapter/page context and correlation ID for the orphan-cleanup runbook. Protected paid/VIP delivery remains `Verification Required`; Admin preview is an authorized server proxy and does not publish provider identifiers.

C04 implements anonymous public comic list/detail and fixed 30-item, one-based Chapter pagination with total metadata. Reader update ordering uses the newest `published_at` of valid Published Chapters, falling back internally to `comic.created_at` only when no Published Chapter exists; Comic metadata edits never affect this order. All projections fail closed to Published Comics and valid Published Chapters and never expose page/provider identities. Its batched Chapter `accessSummary` is deliberately limited to catalog-owned effective price: zero is `Free`, positive is `Locked`. Reading-owned VIP and durable unlock personalization is deferred to R01; rating sort is deferred to IN01.

R01 enriches that Chapter page through Workflows so Catalog does not reference Reading. The enrichment is one batched projection and returns `Unavailable` if a Chapter becomes non-public between catalog and access reads; the manifest endpoint performs its own authoritative publication/page recheck before issuing any URL.

## Acceptance
Cannot publish Comic with zero valid Published Chapters; cannot publish empty Chapter; can publish Chapter while Comic Draft without public access; hide last valid Published Chapter rejected; paid assets never leaked in public metadata; Featured duplicates/max6/unpublished rejected; concurrent reorder conflicts rather than lost updates.
